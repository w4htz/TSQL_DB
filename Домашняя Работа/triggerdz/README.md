# ⚡ Домашняя практическая работа по T-SQL: Триггеры (triggerdz)

## 🎯 Введение и цели проекта
Данный модуль посвящен изучению и практической реализации механизмов активных баз данных, а именно — автоматических программных блоков (триггеров) на языке **Transact-SQL (T-SQL)** в среде Microsoft SQL Server.

Основная цель работы — автоматизация контроля бизнес-логики на уровне сервера баз данных, обеспечение расширенной целостности данных, которая не может быть достигнута стандартными ограничениями (Constraints), а также пошаговое тестирование реакций СУБД на события манипулирования строками.

---

## 📂 Структура и состав каталога
Внутри папки находятся следующие отчетные ресурсы:
* **`triggerdz`** — основной исполняемый скрипт сценария T-SQL, содержащий программный код создания триггеров и тестовые транзакции.
* **`Снимки экрана (7 шт.)`** — подробные графические логи верификации. Скриншоты пошагово фиксируют срабатывание триггеров в режиме реального времени, вывод системных сообщений, состояние виртуальных таблиц и итоговые изменения в таблицах базы данных.

---

## 🛠️ Технологический стек проекта
* **Базовая СУБД:** Microsoft SQL Server (MS SQL Server)
* **Интерфейс администрирования:** SQL Server Management Studio (SSMS)
* **Языковой стандарт:** Transact-SQL (T-SQL)

---

## 🚀 Реализованный функционал и логические слои

### 1. Архитектурное проектирование триггеров
* Реализация триггеров типа **`AFTER` / `FOR`** для реагирования на события модификации данных после проверки стандартных ограничений.
* Применение логики обработки виртуальных системных таблиц **`inserted`** и **`deleted`** для динамического анализа измененных, добавленных или удаленных кортежей.

### 2. Автоматизация бизнес-логики (DML-события)
* Создание обработчиков для событий **`INSERT`**, **`UPDATE`** и **`DELETE`** (или их комбинаций).
* Реализация логики валидации данных, генерации автоматических логов или каскадного обновления связанных полей при изменении родительских записей.

### 3. Комплексное тестирование и перехват исключений
* Написание тестовых DML-запросов, умышленно нарушающих и соблюдающих бизнес-правила, для демонстрации корректности работы перехватчиков.
* Проверка консольного вывода и результирующих таблиц (Result Grid), подтверждающая отсутствие зацикливаний и ошибок времени выполнения.

## 💡 Порядок развертывания решения на локальной машине
1. Перейдите в каталог `triggerdz` и откройте файл скрипта в среде SSMS.
2. Подключитесь к вашему текущему экземпляру SQL Server.
3. Выделите блок кода создания триггеров и выполните его (клавиша **`F5`**).
4. Запустите блоки с тестовыми `INSERT`/`UPDATE` операторами, чтобы увидеть триггерную логику в действии.
5. Сверьте полученный результат с логами отладки на скриншотах в этой папке.
